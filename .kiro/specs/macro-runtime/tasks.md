# Implementation Plan

> **前提（このスペックの外）**: ドキュメントへの変更の**適用経路**（`document-session`）と**取り消し履歴の所有者**（ウィンドウの保持が持つ `data-grid::history::UndoStack`）は実装済みである。本スペックは**エンジン（`crates/macro-runtime`）が変更集合を返し、アダプタ（`src-tauri`）が 1 回の `edit` と 1 対の履歴にまとめる**形を取る（design.md 決定 2 / 3）。`UndoLabel::MacroRun` は本スペックのために予約済みである。
>
> **実行基盤の確定形**は `.kiro/steering/tech.md`「Known Risks」1 にある（専用スレッド + current-thread ランタイム / `resolve` を使わない / `#[op2]` を `async fn` に / 状態は型で受ける）。使い捨てスパイク `target/spike-macro-runtime/` が動く実例である。

- [ ] 1. Foundation: クレートの足場・上流の拡張・結果の型・実行基盤・マクロの記録
- [ ] 1.1 クレートをワークスペースへ追加し、依存の向きを検査に載せる
  - `crates/macro-runtime/` をライブラリクレートとして作り、ワークスペースの `members` に登録する
  - 依存は `document-format` と `schema-engine` の path 依存だけにする。**`tauri` / `data-grid` / `document-session` を依存に持たない**（`structure.md`「ドメインクレートの内部構造」）
  - 実行基盤と周辺のクレートを足す: `deno_core`（`serde_v8` を含む）、`deno_ast`（`transpiling`）、`ts-rs`。`Cargo.toml` の冒頭に依存方針のコメントを置く（なぜ `data-grid` を持たないか = 変更の適用はアダプタの仕事であること）
  - `criterion` を dev-dependency に加え、`[lib] bench = false` と空のベンチファイルを同時に置く（宣言だけでは `cargo bench --no-run` が通らない）
  - **実行ファイルの大きさの実測はここでは行わない**（`src-tauri` へ結線してから測る。5.4 が担う）
  - **観測**: `cargo test -p macro-runtime` と `cargo bench --no-run -p macro-runtime` が通り、`cargo tree -p macro-runtime` に `tauri` / `data-grid` / `document-session` が現れない
  - _Requirements: 2.1, 11.3_

- [x] 1.2 上流 `document-format` にマクロのパートを 1 形足す（形だけ。意味は持たせない）
  - エントリ名の閉じた列挙に 1 形（`macros.json`）を足し、マニフェスト索引・`Parts` の列挙・往復に通す
  - **`Document` にマクロの並びの読み書き口を足す**（`to_parts` / `from_parts` / 構築時の検証を追随させる。`model/` にも触れる）
  - 中身は**マクロの記録の並び**（名前・種別・ソース）とし、**解釈（ソースの検証・能力宣言の読み取り）は本クレートが行う**。上流は形だけを知る（design.md 決定 4）
  - **決定性とフィクスチャを追随させる**: 同一内容 → 同一バイト列の検査、往復の検査、`window_protocol_fixture` を含む既存の期待値
  - **形式版を進めるかはこの作業で決めて記録する**（古いビルドで開いたときの振る舞いを本スペックは所有しない。design.md Revalidation Triggers）
  - **観測**: マクロを 1 件持つ文書を保存 → 開き直して、**ソースがバイト単位で一致し**、既存の決定性検査が通る
  - _Requirements: 1.1, 1.2, 1.5_

- [ ] 1.3 (P) 実行の結果と失敗の表現（3 値・種別・フレーム）
  - **この層が定義する型**: 実行の要求（マクロの記録・上限・対象ウィンドウ）、結果（3 値）、失敗（理由・種別・フレーム）、変更の件数（種別ごとの数）、上限（時間とメモリの対）。**実装はここではなく**、上限の適用は 1.5、変更の集約は 2.3 が持つ（型を 1 箇所に置くことで並列の担当が型で繋がる）
  - 結果を `Ran` / `Failed` / `Aborted` の 3 値とし、**打ち切りを失敗と別の値**にする（打ち切りの種類を持つ）
  - 失敗に、理由・種別（ソースの解釈 / 変換 / 実行 / ホスト API の拒否）・フレーム（マクロ名・行・列・関数名）を持たせる
  - 戻り値の提示用の表現（オブジェクトは JSON）と、出力の並びを結果に含める
  - **観測**: 3 値が型で区別され、失敗のフレームが TypeScript の原位置を指せる形になり、打ち切りの種類が結果から読める
  - _Requirements: 2.3, 2.4, 5.5, 6.1, 6.2, 9.1, 9.3_
  - _Boundary: engine/outcome_

- [x] 1.4 実行基盤の actor（専用スレッド・直列化・実行ごとの isolate）
  - 専用 OS スレッドが current-thread の tokio ランタイムを 1 つ回し、**実行ごとに `JsRuntime` を作って所有スレッドの上で落とす**（design.md 決定 1）。`isolate` の生成は 1 箇所に閉じる
  - 要求は mpsc + oneshot で直列化し、**isolate をスレッドから出さない**。実行中の 2 つ目の要求は「実行中である」として断る
  - 評価は `execute_script` → `run_event_loop(Default::default())` → Promise の状態を読む（**`resolve` を使わない**）。結果は 1.3 の型で返す
  - **観測**: 1 回の評価が戻り値を返し、2 つ目の要求が断られ、**連続 2 回の実行でグローバルが共有されない**（結合検査）
  - _Depends: 1.3_
  - _Requirements: 2.1, 2.2_

- [x] 1.5 時間とメモリの上限・打ち切り・復帰
  - 上限の**型**は 1.3 が持つ。ここが持つのは適用と打ち切りと復帰である
  - 時間の上限はタイマースレッドが `thread_safe_handle().terminate_execution()` を呼ぶ。メモリの上限は `create_params` の `heap_limits` + `add_near_heap_limit_callback` の中で同じ終了経路へ合流させる（**callback を付け忘れると V8 がプロセスを abort させる**）
  - **種類（時間 / メモリ）を記録**し、1.3 の `Aborted` に載せる。次の実行の前に `cancel_terminate_execution()` を呼ぶ
  - 打ち切りの後始末（isolate の破棄・actor の状態の戻し）を行い、**同じ actor で次の実行ができる**ようにする
  - **観測**: 無限ループが既定 30 秒で打ち切られ、大量確保がメモリの上限で打ち切られ、**どちらの後も次の実行が成功する**（結合検査）
  - _Depends: 1.4_
  - _Requirements: 6.1, 6.2, 6.4_

- [x] 1.6 マクロの記録と能力宣言の解釈
  - 名前・種別（TypeScript / JavaScript）・ソースを値オブジェクトとして定義し、名前の一意性と置き換え（同じ名前の保存）の規則を表す
  - ソース先頭の**能力宣言**（ファイルの読み・書き・ネットワーク）を解析する。綴りの揺れ・重複・未知の能力を判別可能な誤りとして返す
  - 種別とソースの整合（TypeScript のソースに構文誤りがあっても**ここでは止めない**。変換の段で扱う）を表す
  - 上流のパート（1.2）との往復: 記録の並び → 保存 → 開き直し
  - **観測**: 宣言の解析が綴りの揺れを正規化し、未知の能力を名前つきで拒み、**保存と読み込みの間でソースが変わらない**
  - _Depends: 1.2_
  - _Requirements: 1.4, 1.5, 1.6, 1.7, 3.2, 3.3, 8.4, 8.5_

- [ ] 2. Core: ホスト API（宣言表・値・変更の集約・読み）
- [x] 2.1 ホスト API の宣言表を作る（登録・門・型の唯一の源）
  - API の名前・引数・戻り値の型・**必要とする能力**を 1 つの表に並べる（design.md 決定 5）
  - 能力の門: マクロの宣言（1.6）に無い能力を要する API は、**呼び出しの前に**拒否する（理由に能力の名前を含む）
  - **能力の欄を必須にする**（「能力不要」も明示的な `None` として書く。既定を「能力不要」にしない）
  - 宣言と実装の一致を検査する（宣言にある op がすべて登録され、登録された op がすべて宣言にある）
  - **観測**: 宣言にある API はすべて呼べ、宣言に無い API は呼べない。能力の欄が欠けた宣言を足すと検査が落ちる
  - _Depends: 1.6_
  - _Requirements: 4.1, 8.1, 8.3, 8.4, 10.1_

- [x] 2.2 (P) 値の写像（スキーマの値 ⇄ JavaScript の値）
  - `CellValue` の全変種（整数・小数・真偽・文字列・日時・入れ子・ANY・添付・値なし）を JavaScript の値へ写し、書き戻しで往復させる
  - 入れ子と ANY は構造として渡し、書き戻しでも同じ構造に戻す
  - **範囲の読みでコピーを増やさない形**（借用で渡す経路）を用意する
  - **観測**: 全変種の往復が一致し、書き戻した値が上流の検証へ渡せる形になっている
  - _Requirements: 4.2, 4.3_
  - _Boundary: host/value_

- [ ] 2.3 (P) 未適用の変更集合（集約と件数）
  - セルの書き込み・行の追加・行の削除・行の複製を、**適用せずに集める**型を定義する（件数の型は 1.3 が持つ）
  - **同じセルへの複数の書き込みは後ろが残る**。適用の順序（追加 → 値 → 削除）を型と手順で表す
  - 種別ごとの件数を数える（実行の結果として提示する。要件 5.5）
  - 適用できる行の識別子だけを受け付ける（適用前に存在しない行を指したら、理由つきで拒む）
  - **観測**: 集約だけでは文書が変わらず、件数が種別ごとに数えられ、存在しない行の指定が理由つきで拒まれる
  - _Depends: 1.3_
  - _Requirements: 5.3, 5.4, 5.5_
  - _Boundary: host/changes_

- [x] 2.4 範囲の読みと重ね合わせ（自分の書き込みを読む）
  - 行の範囲を**1 回の呼び出しで**読む口を作る（行ごとの呼び出しを要求しない。要件 4.4 / 11.3）
  - シートの一覧・列の宣言（型情報）・行数を読む口を作る。列の宣言は読み取り専用であり、書き換えの要求は理由つきで拒む
  - 読みは**自分の書き込みの重ね合わせ**（2.3）を見る。追加した行の中身は `insert` に渡した値としてのみ扱い、後から読む要求は理由つきで拒む
  - **観測**: 20 万セル級の範囲が 1 回の呼び出しで読め、書いたセルを読むと書いた値が返り、スキーマの書き換えが拒まれる
  - _Depends: 2.2, 2.3_
  - _Requirements: 4.1, 4.4, 4.5_
  - _Boundary: host/read, host/overlay_

- [ ] 3. Core: 実行（変換・結線・型定義）
- [x] 3.1 (P) TypeScript の変換経路（型注釈の除去とソースマップ）
  - 変換を**モジュールの解決の段**（`ModuleLoader::load`）の中で行い、変換結果に `sourceMappingURL` を付ける（`extension_transpiler` は拡張専用であり使わない）
  - 種別が JavaScript のソースは変換しない。解決できない取り込みは**名前を挙げて**失敗させる
  - 構文誤りは位置（行・列）つきの失敗（1.3 の型）として返す
  - **観測**: 型注釈の誤りでは止まらず、構文誤りは行・列つきで返り、**例外のフレームが TypeScript の原位置を指す**
  - _Depends: 1.3, 1.6_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_
  - _Boundary: engine/transpile_

- [x] 3.2 isolate の組み立て（op の登録・console の取り込み・変換の結線）
  - 宣言表（2.1）から op を登録し、能力の門（2.1）を通して `HostPort`（2.2 / 2.3 / 2.4）へ渡す
  - `console` の出力を**ホストへ戻す**（アプリの標準出力へ漏らさない）。順序を保つ
  - 変換（3.1）をモジュールの解決へ結線し、ソースマップを実行基盤へ渡す。`HostPort` はアダプタが差し込む（エンジンは実装を知らない）
  - **観測**: マクロの `console.log` が実行の結果として回収され、ホスト API の呼び出しが重ね合わせと変更集合へ届き、`import` できない名前は理由つきで失敗する
  - _Depends: 1.3, 1.4, 1.5, 2.1, 2.2, 2.3, 2.4, 3.1_
  - _Requirements: 2.3, 4.1, 5.1, 9.2_

- [x] 3.3 (P) マクロ向け型定義の生成と乖離の検出
  - 宣言表（2.1）と `ts-rs` の型から `types/macro-host.d.ts` を組み立てる生成器を置く（**手書きしない**。`structure.md`「マクロ向け型定義」）
  - 生成物を追跡し、**生成器の出力とのバイト一致**を検査する（`src/ipc/bindings.ts` と同じ運用）
  - 能力を要する API は、宣言のコメントに能力名を書く（補完で見える。要件 8.2 の提示と一致させる）
  - 型の無い API を公開できないようにする（宣言の型が無ければ生成が失敗する）
  - **観測**: 生成物が再生成と一致し、宣言表の全 API が `.d.ts` に現れ、型の無い API を足すと検査が落ちる
  - _Depends: 2.1_
  - _Requirements: 4.6, 10.1, 10.2, 10.3_
  - _Boundary: types_

- [ ] 4. Integration: アダプタと実行の面
- [x] 4.1 (P) ホストの縫い目を文書へ繋ぐ（アダプタ）
  - `HostPort` を実装する: シートの一覧・列の宣言・範囲の読みを `document-session` / `schema-engine` から供給する
  - 能力を要する口（ファイルの読み・書き・ネットワーク）を実装し、**門（2.1）を通った呼び出しだけ**が届くようにする。ネットワークは既存の依存（HTTP クライアント）をアダプタ側で使う
  - 出力（console）と実行の要求を actor へ渡し、結果を境界の形へ写す
  - **観測**: 実文書のシート・列・行がマクロから読め、宣言の無いファイル読みが拒まれる
  - _Depends: 2.4, 3.2_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 8.1, 8.3_
  - _Boundary: src-tauri/macro_host_

- [x] 4.2 (P) 変更集合の適用と 1 回の取り消し（アダプタ）
  - 変更集合（2.3）を `data-grid` の編集命令へ写し、`document-session` の `edit` の**閉包 1 回**の中で全部適用する
  - 履歴へは `UndoLabel::MacroRun` の**1 対だけ**を積む（逆命令は適用した命令の並びから組む）
  - 適用の前にシートを照合し、1 つでも食い違えば**何も書かずに**拒む（既存の合成の規律に従う）
  - 実行が失敗・打ち切りで終わったときは**何も適用しない**
  - **観測**: マクロの変更が**取り消し 1 回で全部戻り**、やり直し 1 回で全部戻り、適用の失敗ではドキュメントが変わらない
  - _Depends: 2.3_
  - _Requirements: 5.1, 5.2, 6.3, 7.1, 7.2, 7.3, 7.4_
  - _Boundary: src-tauri/macro_apply_

- [x] 4.3 導線と境界の型（コマンド 4 本・許可・メニュー・設定・記録）
  - 境界の型（一覧・保存・削除・実行の要求と応答）を `app-shell` の IPC に足し、生成物を再生成してドリフト検査を通す。**一覧は「解釈できなかった理由」を含む**（要件 1.4）
  - コマンド 4 本を `src-tauri` に置き、`command_root!` と許可（`permissions/app.toml`）へ登録する
  - **マクロの保存と削除は `document-session` の `edit` の閉包 1 回で行う**（未保存の印と版の記録に乗る。`structure.md`「セッションの所有の規約」）
  - メニューに実行の導線を 1 項目足し、**項目数を主張している既存の検査器（Linux と macOS の 2 本）を追随させる**（越える境界である）
  - 設定に時間とメモリの上限の 2 鍵を足し（既定 30 秒 / 512 MB）、実行のときに解決してエンジンへ渡す
  - 実行 1 回につき診断の記録へ 1 行残す（マクロ名・種別・結果・打ち切りの種類・変更の件数・所要。**ソースと値は出さない**）
  - **観測**: 4 本のコマンドが許可どおりに呼べ、保存と削除が未保存の印を立て、メニューに項目が現れ、設定の変更が次の実行から効き、実行のたびに記録が 1 行増える
  - _Depends: 4.1, 4.2_
  - _Requirements: 1.3, 1.4, 1.6, 1.7, 2.1, 2.5, 2.6, 6.5, 8.2_

- [x] 4.4 実行の面（一覧の提示・能力の提示・結果・失敗）
  - **開いた時点でその文書のマクロの一覧を出す**（名前・種別・解釈できなかった理由。要件 1.3 / 1.4）。実行の入口はメニューの 1 項目であり、押すとその一覧から選ばせる
  - 選ばれたマクロの**宣言されている能力**を実行の前に示す（要件 8.2）
  - 結果を 1 つの面に出す（戻り値・出力・変更の件数・失敗の理由とフレーム・打ち切りの種類。要件 2.5）
  - 実行中は「実行中」を示し、**表の操作と表示を止めない**。実行できるマクロが 1 つも無ければ導線を提示しない（要件 2.7）
  - **観測**: 実起動で「一覧 → 能力の提示 → 実行 → 結果」が通り、失敗と打ち切りがそれぞれ固有の提示になり、解釈できないマクロが理由つきで一覧に残る
  - _Depends: 4.3_
  - _Requirements: 1.3, 1.4, 2.3, 2.4, 2.5, 2.7, 8.2, 9.1, 9.2, 9.3_

- [ ] 5. Validation: 実起動の観測・予算・記録
- [x] 5.1 検証専用の引き金とマクロ入りの標本（観測の前提）
  - 非既定 feature（`verification-triggers`）と環境変数 1 系統で、**実行の観測を起動時に仕込める**ようにする（検証専用の初期画面または引き金。既定のビルドには読み取りが入らない）
  - マクロを 1 件持つ標本の文書を用意する（上流の生成器を使い、**手で作った文書を置かない**）
  - **観測**: 検証用のビルドを起動すると、仕込まれたマクロが一覧に現れ、既定のビルドでは同じ起動が仕込みを一切読まない
  - _Depends: 1.2, 4.3_
  - _Requirements: 1.2, 2.1_

- [x] 5.2 実起動の観測の検査器と 3 OS の段（反証を含む）
  - POSIX の検査器を置き、**診断の記録を読み口**にして要件値で判定する（`data-grid` の 9.2 が確立した形）
  - 見るもの: 実行の成功と変更の件数・失敗の理由とフレーム・打ち切りの提示とその後の操作可能性・能力の拒否・保存と開き直しの往復
  - 反証: 配布物を渡すと検査器が非 0 で落ちること（観測の行が現れない）
  - 3 OS の段を既存のマトリクスへ 1 段ずつ足す（**新しいジョブを作らない**）。macOS / Windows はこの開発機では走らせられないため、その旨を段の冒頭に書く

## Implementation Notes

### 4.2 が実測した上流の性能問題（**所有は `data-grid` / `document-format`**）

- **観測**: 10 万行の変更の**取り消し**が 35.2 秒（同じ条件の適用は 259.9ms）。
- **原因**: `data-grid` の `write_material_rows` が行ごとに `Document::set_row_values` を呼び、
  `Document` → `Sheet::set_row_values` が行を**線形探索**する（`rows.iter_mut().find`）。
  費用は 行数 × 書いた行数。`set_cells` は既に「索引を 1 度作る」規律を採っている。
- **回避できない理由**: `data-grid` の命令語彙には行の値を一括で置換する口が `RestoreValues` しかなく、
  写像側（`src-tauri/src/macro_apply.rs`）で回避する道が無い。`EditCommand::SetCells` は「打たれた
  文字」で判定を通るため値の変種が変わり、行幅も戻せない。
- **したがって**: マクロの変更を大きく取り消すと 35 秒待たされる（**製品から見える**）。修正は上流
  （`data-grid` の `write_material_rows` が行の索引を 1 度作る、または `document-format` が位置で書く口を
  持つ）で行う。`macro-runtime` の側では直さない。
- **テストへの影響**: 10 万行の往復そのものは回していない（回すと 35 秒）。往復の意味論は小さい標本で、
  10 万行は適用と材料の被覆で固定している（`macro_apply` のテストの doc に実測値つきで記載）。

### 5.1 が置いたもの（引き金と標本。**5.2 が読む前提**）

- **引き金**: `JXCEL_VERIFICATION_MACRO_RUN=<マクロ名>`（`verification-triggers` の下。**5.2 で `,` 区切りの並びへ拡張** — 打ち切りの後も操作できることを**同じ起動の中で続けて別のマクロが走る**形で観測するため。既存の一族（`SESSION` / `BULK_ROWS`）と同じ区切り）。
  `src-tauri/src/window/mod.rs` の `macro_run_script`）＋ `JXCEL_VERIFICATION_INITIAL_SCREEN=grid`。
  起動時に `src/shell/verificationMacroRun.ts` が**製品の面の保持**（`MACRO_SURFACE_STORE`）を通して
  「一覧 → 選択 → 実行」を駆動する（**押下ではなく仕込み**である理由は 4.4 の申し送り: この機械の
  WebKitGTK は DOM をアクセシビリティの木へ露出しない）。**グリッドの初期画面が要る** — マクロの変更を
  適用するには、そのウィンドウでグリッドがシートを開いている必要がある（`grid_open_sheet` が先）。
- **記録**: 製品の `macro_run:` の 1 行に加えて、検証専用の観測の 1 行
  （`マクロの観測: {…}`。`src-tauri/src/lifecycle.rs` の `register_macro_observation_listener`）が出る。
  運ぶのは 一覧の件数と名前・選んだ名前・宣言されている能力・結果の 3 値・変更の件数・打ち切りの種類・
  失敗の層と理由とフレーム。**製品の行は失敗の理由とフレームを持たない**（要件 8.3 の帰結）ので、
  5.2 の「失敗の理由とフレーム」「能力の拒否」はこの行が唯一の読み口である。
- **標本**: `cargo run -p macro-runtime --example make-macro-document --features verification-samples -- <出力先>`。
  `crates/macro-runtime/examples/make-macro-document.rs` が `document-format` と `schema-engine` の
  公開面だけで「1 シート（在庫: 品名 / 数量、3 行）＋マクロ 1 件（標本の記入。1 セルだけ書く）」を組み立て、
  保存・開き直し・中身の 1 行を出す。**2 回の生成はバイト列として一致しない**（識別子が ULID である）が、
  `標本の内容:` の行は一致する（実測で一致を確認）。
- **落とし穴（実測。5.2 / 5.3 が踏まないように）**: `SchemaPart::empty()`（`{"root":null}`）を持つ文書は
  **表を開けない** — 表を開く経路は宣言から列の計画を組み、列 0 本の計画は `GridSession::open` が拒む。
  症状は `grid_open_sheet: … 失敗 = ドキュメントを扱えない` の 1 行だけで、理由は記録に出ない
  （`IpcError` の `Display` が詳細を落とす）。標本は**列の宣言を型つきで持つ**必要がある
  （本タスクは `schema-engine` の正準出力（`schema_to_text`）＋ `SchemaPart::parse` で作っている）。
- **既定のビルドの非読み取り**（検査で固定）: 既定の `target/debug/jxcel` に `JXCEL_VERIFICATION` /
  `JXCEL_VERIFICATION_MACRO_RUN` / 観測のイベント名 / 記録の文言が **0 件**（`strings -a`）であり、
  既定の `dist/` に対して `scripts/check-shipping-bundle.sh` が 0 で終わる（**同スクリプトの禁止語に
  `verificationMacroRun` を足した**ので、混入すれば落ちる。検証用の形の `dist/` に対しては実際に非 0 で
  落ちることも実測した）。
