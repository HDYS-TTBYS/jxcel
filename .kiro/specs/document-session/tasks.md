# Implementation Plan

> **前提（このスペックの外）**: アプリ全体の終了（`request_exit`）は `app-shell` が無条件に行い、本スペックは関与しない（`design.md`「Risks & Mitigations」）。下流の `data-grid` は **6.1〜6.3 / 群 8 / 9.2・9.3** が本スペックの完了を前提にしており、`design.md` の Revalidation Trigger に従って `document-session` の公開面が確定した時点で `data-grid/design.md` を再検証する。**`document-format` の 3 ファイル（`model/mod.rs` / `model/sheet.rs` / `lib.rs`）は `data-grid` も編集する**ため、本スペックの 1.2 を**先に**実装し、`data-grid` が後から行の削除と位置指定の挿入を足す（後発側が再輸出と決定性テストを再確認する）。

- [x] 1. Foundation: クレートの足場・上流の拡張・共有の道具
- [x] 1.1 クレートをワークスペースへ追加し、tauri 非依存を検査に載せる
  - `crates/document-session/` をライブラリクレートとして作り、ワークスペースの `members` に登録する
  - `document-format` と `app-shell` への path 依存だけを持つ。`tauri` を推移的にも入れない
  - `Cargo.toml` の冒頭に依存方針のコメントを置く（依存してよい兄弟は 2 つだけ、位置と識別子を境界へ出さない理由、ベンチを持つ理由）
  - `criterion` を dev-dependency に加え、`[lib] bench = false` と併せてベンチターゲットを宣言し、**同時に空のベンチファイルを置く**（宣言だけでは `cargo bench --no-run` が通らない）
  - **CI の段を足す必要はない。**コアクレートの tauri 非依存検査は引数なしで `crates/` 配下を全列挙する形であり、新しいクレートは自動的に対象に入る。**対象に入っていることを実際に確かめる**
  - `cargo test` と `cargo bench --no-run` が成功し、`cargo tree -p document-session` に `tauri` が現れない
  - _Requirements: 8.1_

- [x] 1.2 上流のドキュメントモデルに一括のセル書き換えを足す
  - `Document` に、行識別子と**列の添字**（`Sheet::columns` の並びに対する位置）と値の並びを受ける一括の書き換えを追加する
  - **行の索引を 1 度だけ作る**（`set_row_values` を繰り返すと O(行数 × 変更数) になるため。`crates/document-format/src/model/sheet.rs`）。変更しない行と列の値に触れない
  - 事前検査を 1 パスで行い、未知のシート・未知の行・範囲外の列を判別可能な変種として返す。**1 つでも不正ならどのセルも変更しない**（部分適用なし）
  - 行の現在の値数より後ろへの書き込みは、間を値なしで埋める
  - モデル局所の誤り型として定義し、既存の `UnknownRow` / `ReorderError` と同じ規律（文脈のみ・表示文言なし）に従う
  - **決定的な出力と往復の契約に触れない**（変わるのは行の値だけである）ことを、`cargo test -p document-format` の決定性テストが通ることで示す
  - 同じ入力の再適用が同じ結果になり、**行の集合・並び・識別子が変わらない**ことをテストで示す
  - **`data-grid` が後から足す行の削除と位置指定の挿入と衝突しない**ことを確認する（本スペックは行の集合を変える入口を足さない。`design.md` の Revalidation Triggers）
  - _Requirements: 3.5, 3.7_

- [x] 1.3 セッションの状態と誤りの型を定義する
  - 出所（新規 / ファイルの位置）、未保存、変更の版、シートの要約を持つ状態の型を定義する
  - 保持していない・別の操作が進行中・未保存のため差し替えできない・読み込みに失敗した、を判別可能な列挙体として定義する
  - 保存の結果を「保存した / 保存先が要る / 取り消した / 失敗した」の判別可能な列挙体として定義する。**取り消しを誤りにしない**
  - **表示用の文言を持たせない**（文言は適応層が組み立てる）。形式の側の誤りはそのまま運ぶ
  - 閉じてよいかの答えを 2 値で定義する（理由の文言は持たない）
  - すべての変種が生成・照合でき、`Send + Sync` であることをコンパイル時に表明するテストを書く
  - _Requirements: 4.3, 5.1, 6.1, 6.6_

- [x] 1.4 テストとベンチが共有する標本の生成器を用意する
  - 指定した行数・列数のシートを持つドキュメントを、**上流の公開 API だけ**で組み立てる生成器をテスト用の共有モジュールに置く（`DocumentParts::from_entries` + `from_parts`。形式の側の内部モジュールに触れない）
  - 保存と読み込みの往復で使えるよう、一時ディレクトリへ書き出す補助を持つ
  - ベンチからは相対パス指定でこの共有モジュールを取り込む（`tests/` のモジュールはそのままではベンチから参照できない）
  - 10 万行 × 30 列の標本が生成でき、同じ引数なら常に同じ内容になることをテストで示す
  - **同じ生成器がクレートごとに写される状態を悪化させない**ことを `research.md` のリスクとして記録したままにする（集約はスペック横断の変更になるため本スペックでは行わない）
  - _Requirements: 8.1_

- [x] 2. Core: セッションの表と状態機械
- [x] 2.1 1 つのセッションの状態機械を実装する
  - 出所（新規 / ファイルの位置）と保持する文書を 1 対で持つ。**未解決の状態を持ち、生成要求の位置が与えられたときに 1 度だけ読み込む**（2 回目のアクセスで読み込みが起きない）
  - **セッションを作るのは適応層の 3 つの入口（起動時の位置を渡す解決 / ファイルの引き渡し / 新規作成）だけ**とし、読み取り・変更の適用・保存・破棄の印は未解決のウィンドウに対して失敗を返す（生成要求を読めるのは呼び出し元だけであり、破棄の購読を伴わないセッションが生まれる経路を塞ぐ）
  - **ファイルの引き渡しの入口をコアに置く**: 利用者が選んだ位置を読み込む。**未保存なら拒否**し、**読み込みに失敗しても保持している文書を変えない**。起動時の解決と違い、保持済み・失敗の記憶のどちらからでも**読み直して出所を更新する**（利用者の明示の操作であるため）
  - **未保存の印と版の更新は、文書のロックを保持したまま行う**（判定と更新を同じ臨界区間に入れる。でなければ「未保存でない」と判定した直後の変更が差し替えで黙って失われる）。**文書が入れ替わる操作（読み込みの完了・新規作成）でも版を 1 進める**（下流は版の変化で「変わった」ことを知るため）
  - 未保存と変更の版を**文書のロックの外の原子値**として持つ（閉じてよいかの問い合わせがロックを待たないため）
  - 読み込みに失敗したときは状態を変えずに理由を返す。読み込みが進行中の同じウィンドウへの読み込みと新規作成は**待たずに失敗させる**
  - 未保存の印を落とす操作（保存しない）を、利用者の明示の指示として与える
  - 閉じてよいかは未保存の原子値だけを読み、**適用の進行中でも待たない**ことを、長い適用を別スレッドで走らせて観測するテストで示す
  - _Requirements: 1.2, 1.8, 2.1, 2.3, 2.5, 4.4, 4.6, 7.1, 7.2, 7.3_

- [x] 2.2 保存の経路を実装する
  - 出所へ書き出す経路と、選ばれた位置へ書き出して以後の出所にする経路の 2 つを与える。出所が無いときは「保存先が要る」を結果として返す（提示は適応層の仕事）
  - 保存は**文書のロックの下で 1 パス**として行い、書き出した内容と保持している内容が食い違わない（保存の進行中に到着した適用は、保存の完了を待ってから行われる）
  - 成功で未保存を落とし、失敗と取り消しでは未保存を保つ。**書き出したバイト列が、形式の側へ直接書き出したバイト列と一致する**ことをテストで示す
  - 選ばれた位置への保存のあと、同じ指示で同じ内容がその位置へ書き出される（出所が更新されている）ことをテストで示す
  - _Requirements: 4.5, 5.1, 5.4, 5.5, 5.7, 5.8_

- [x] 2.3 ウィンドウ → セッションの表を実装する
  - ウィンドウの識別子を鍵とし、1 つのウィンドウにつき高々 1 つのセッションを持つ表を作る
  - 表のロックは**参照と挿入のためだけ**に取り、セッションごとのロックを分ける（10 万行の適用が他のウィンドウを待たせない）
  - 破棄されたウィンドウのセッションを忘れる操作（`forget`）を持つ。**他のウィンドウの文書と未保存の状態を変えない**。呼び出し元は 3.3 の購読と掃除の経路である
  - 表とセッションが `Send + Sync` であることをコンパイル時に表明する
  - 2 つのウィンドウで、一方の変更・保存・破棄が他方に影響しないことをテストで示す
  - _Requirements: 1.1, 1.5, 3.6_

- [x] 2.4 変更の適用の口を実装する
  - **セッションのロックの内側で**閉包へ文書の可変参照を渡し、閉包の戻り値をそのまま返す。**借用を呼び出しの外へ出さない**
  - 適用のあとに**版を 1 進め、未保存の印を立てる**。閉包が失敗を返した場合も印を立てる（保守側に倒す）。**記録（版と未保存）は文書のロックを保持したまま行う**（判定と更新を同じ臨界区間に入れ、差し替えとの競合で変更が黙って失われないようにする）
  - 読み取りの口を同じロックで提供し、適用中に到着した読み取りには**適用済みの最新**を返す
  - 変更の語彙を持たない（何をどう変えるかは要求側の所有である）。`document-format` を直接呼ぶ
  - **閉包の内側からセッションを呼び返してはならない**（再入禁止）ことを doc に明記する
  - 1 回の適用で版がちょうど 1 進むこと、読み取りと状態の取得では版と未保存が変わらないことをテストで示す
  - **他方のウィンドウの未保存が変わらないことを、実際に印を立てた状態で観測する**（2.3 では `unsaved` を立てる経路が無いため「他方の未保存が変わらない」側が空振りだった。ここで印を立てられるようになるので、表の側の独立性テストにこの観測を足す）
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 4.1, 4.2_

- [x] 2.5 公開面を組み立て、根の再輸出に集める
  - 解決・読み取り・変更の適用・状態・保存・保存先を指定した保存・破棄の印・新規作成・閉じてよいか・破棄 を 1 つの操作口として公開する
  - モジュール冒頭に層の鎖（`error / state → session → change → table → api`）を書き、**左の層だけを参照する**
  - 下位モジュールは `pub mod` のままとし、根に再輸出を並べる（下流は根の名前だけを使う）
  - 適応層が保持できるよう、操作口は `Send + Sync`（コンパイル時に表明する）
  - 根の名前だけで全経路を通す統合テストを書く
  - **記録しない可変の貸出口（`with_document_mut`）が production から使われていないことを確かめ、不要なら削除するか `#[cfg(test)]` に閉じる**（そこから変更すると未保存の印が立たず、要件 4.1 の抜け道になる。production の可変経路は `change::edit` ただ 1 つであることを固定する）
  - _Requirements: 1.4, 3.1_

- [x] 3. Integration: 適応層と境界
- [x] 3.1 境界用の型を定義し、生成物を更新する
  - ドキュメントの名前・出所・未保存・シートの一覧（識別子は文字列、件数は 32 ビット以下）を境界用の型として定義する
  - 状態（保持していない / 保持している / 読み込めなかった理由）と、保存の結果・新規作成の結果を判別可能な合併型として定義する
  - **位置（`PathBuf`）を境界へ出さない。**名前はファイル名のみとする
  - 型を置けるのは `crates/app-shell/src/ipc/` の下だけである（`ts-rs` の derive の唯一の許された場所）。応答の具体形を `render_bindings` に宣言し、生成物を再生成する
  - 経路レベルの失敗のために `IpcError` にドキュメントの変種を足す（ドメインの失敗は封筒の成功腕に載せる）
  - **状態が変わったことを伝えるイベント名**（`DOCUMENT_SESSION_CHANGED_EVENT = "document_session_changed"` の 1 種）を境界へ置き、生成物に定数として出す（綴りを手で書かず、生成物を参照する）
  - **`describeIpcError` に新しい種別の分岐を足す**（`src/ipc/client.ts`。網羅分岐が `assertNever` で新しい種別をコンパイルエラーにするため、足さないと型検査が落ちる）
  - `cargo run -p app-shell --bin generate-bindings` のあと `cargo test -p app-shell --test bindings_drift` と `npm run typecheck` が通る
  - _Requirements: 1.6, 1.7, 7.1_

- [x] 3.2 ドキュメント所有者の宿主を連鎖で設置する
  - `DocumentHost` を実装し、**設置前の宿主を内側に持つ**。`may_close` は未保存なら拒否、そうでなければ内側へ委ねる。`attach` は**コアの引き渡しの入口**（未保存なら拒否し、失敗しても既存の文書を変えない）を通してから内側へも渡す
  - 未解決のウィンドウの `may_close` では**解決を試みない**（読み込みは秒単位かかり、まだ何も変更されていない）
  - 設置は現在の宿主を取り出してから行う。**これにより `verification-triggers` の検証用宿主（拒否の実測と引き渡しの記録）が保存される**
  - 拒否の理由の文言はここで組み立てる（形式の側の誤りを利用者へ伝える文字列を含む）
  - 起動の結線は `dialog::install` の直後の 1 行とする
  - 連鎖の順序（セッション → 内側）と、未保存のウィンドウの拒否が検証用の宿主を壊さないことをテストで示す
  - _Requirements: 1.3, 2.2, 4.6, 6.1_

- [x] 3.3 ウィンドウの破棄でセッションを手放す
  - セッションを作る 3 つの入口で、**ラベルでウィンドウを引き、破棄の通知を購読してから**表へ挿入する。ウィンドウを引けないときは何も作らない。購読は `WebviewWindow::on_window_event` を使い、通知では表から取り除く操作（`forget`）を呼ぶ。**適応層側の登録済みラベルの集合**で「ウィンドウ 1 つにつき 1 回」を保証する
  - **app-shell の破棄通知（メニューの更新とレジストリの掃除）には触れない。**自前の購読を隣に足すだけで、app-shell 側の変更を要しない
  - 登録は戻り値を持たないため失敗を検出できない。**取得と登録の間に破棄された場合に備え、適応層の入口でラベルのウィンドウが引けないときは先に表から取り除く掃除の経路**を併せて持つ
  - 実際に窓を閉じたあと、同じラベルの状態が「保持していない」へ戻り、**他の窓の未保存が変わらない**ことを実画面とテストの双方で示す。掃除の経路も別途テストで示す
  - _Requirements: 1.5_

- [x] 3.4 コマンドを登録し、権限を与える
  - 状態・保存・新規作成・破棄の印の 4 つを、封筒つきのコマンドとして登録する
  - 呼び出し元ウィンドウは**基盤が注入する `WebviewWindow` から取る**（ペイロードで受け取らない）
  - 保存は非同期コマンドとし、保存と保存先の提示を `spawn_blocking` に載せる（イベントループとランタイムのワーカーを塞がない）
  - 状態の問い合わせで、**ウィンドウの生成要求の位置を読んでセッションを確定させる**（起動時に指定されたドキュメントの読み込みはここが引き金になる）
  - **状態を変えた操作（読み込み・新規作成・保存・破棄の印・破棄）のあとに、対象ウィンドウへ `document_session_changed` を 1 回送る**。フロントエンドはこれを購読して問い合わせ直す（イベントは状態を運ばない）
  - 5 点セットを揃える: 名前の定数と `COMMAND_NAMES`、自分のモジュールのハンドラ、登録の根への 1 行ずつ、権限ブロック 4 件と与える集合への所属、生成物の再生成
  - 登録名と権限の一致の検査が 4 つすべてについて通り、保持していないウィンドウへの状態の問い合わせが「保持していない」を返す
  - _Requirements: 1.6, 1.7, 2.4, 5.1, 5.3, 7.1, 7.4_

- [x] 3.5 保存先の選択を提示する
  - 親ウィンドウを必ず指定した保存用の選択を 1 つ足す（Linux は `gtk` の保存動作、Windows / macOS は `rfd` の保存）。既定の提案名を与える
  - 取り消しと「提示できなかった」を区別して返す（取り消しは正常な結果である）
  - **位置はコマンドの応答に含めない。**提示は保存コマンドの内側で完結させる
  - `tauri-plugin-dialog` / `tauri-plugin-fs` を依存に入れない（`scripts/check-forbidden-plugins.sh` が固定する）
  - 取り消しのときに書き出しが起きず、未保存が保たれることをテストと実画面の双方で確かめる
  - _Requirements: 2.4, 5.2, 5.3_

- [x] 3.6 「新規」と「保存」をメニューへ登録する
  - 既存のメニュー登録口を通して 2 つの項目を登録し、ショートカットはプラットフォームで解決した綴りを渡す
  - 活性化の対象ウィンドウの解決と、イベントループを塞がない実行モデルは既存の「開く…」の実装をそのまま写す
  - ショートカットの競合は登録時に報告させる（黙って片方を捨てない）
  - 項目の選択が対応するコマンドと同じ経路を通る（画面からの操作とメニューからの操作で結果が一致する）ことをテストで示す
  - _Requirements: 5.1, 7.1_

- [x] 4. Integration: フロントエンド
- [x] 4.1 (P) コマンドの薄いラッパを用意する
  - 状態・保存・新規作成・破棄の印の 4 つを呼ぶ薄いラッパを境界の隣に置く。**封筒を包み直さない**（包むとドメインの失敗が成功として報告される）
  - コマンド名は生成物の定数を参照し、文字列リテラルで書かない
  - **イベント名も生成物の定数を参照し、状態変化の購読（再問い合わせの引き金）を与える**
  - 型は生成物から取り込み、独自に定義しない
  - 型検査と lint が通る
  - _Requirements: 1.6, 1.7, 5.1, 7.1_
  - _Boundary: DocumentCommands_
  - _Depends: 3.1_

- [x] 4.2 終了前の問いを提示し、差し替え口を足す
  - 終了拒否の購読に**拒否の提示の差し替え口を 1 つだけ**足す。既定は現行の記録のみとし、app-shell の振る舞いを変えない

## Implementation Notes

- **1.2**: `Document::set_cells` の同一呼び出し内に**同じ行・同じ列の重複**が含まれる場合の意味論は「入力順の last-wins」である（決定的だが仕様書に明記が無く、テストも無い）。個別のレビューでは非阻害と判定された。下流（`data-grid` の貼り付け）が重複を生成しうるなら、契約として明記するか、重複を弾くかの判断が要る。
- **1.3**: 実装者が design の逐語に無い追加を 2 つ入れた（レビューで非阻害と判定）: (i) `SessionError::Read` の `source` に `#[from]` を付けた（`DocumentError` からの暗黙変換が増える。読み込み以外の `DocumentError` も `Read` に化けうるので、**書き出しの失敗は `SaveReport::Failed` に閉じる**という区別を崩さないこと）、(ii) `SaveReport` に手書きの `Display` と `std::error::Error` を与えた（`Cancelled` は正常な結果であり、`source()` は `Failed` のときだけ `Some`）。`SheetSummary` のフィールド型（`id: SheetId` / `columns: usize` / `rows: usize`）は design に無かったため design へ追記した。
- **2.1**: 実装で確定した設計の補完（design へ反映済み）: (i) `Inner` に `Unavailable { reason }` を追加（読み込みの失敗を覚えないと、画面の問い合わせのたびに秒単位の再読み込みが起きる）、(ii) **`attach`（利用者が選んだ位置の引き渡し）をコアの入口として追加**（当初の計画に欠けていた。未保存なら拒否・失敗しても保持中の文書を変えない・`Unavailable` からは読み直す）、(iii) **版は「文書が入れ替わるか変更が適用されたとき」に 1 進む**（適用回数ではない。入れ替えで据え置くと下流の窓が古い内容を表示し続ける）、(iv) **未保存と版の更新は文書のロックを保持したまま行う**（判定と更新を同じ臨界区間に入れないと、差し替えで変更が黙って失われる）、(v) 新規シートの既定名は `NEW_SHEET_NAME = "シート1"`、(vi) `may_close` の非ブロッキングは**デッドロック検出のための時間切れ**で固定する（ハングさせない。`verification.md` が禁じる「速度の証拠としての閾値」とは別物である旨をコメントに明記）、(vii) `#[allow(dead_code)]` の seam は 3 箇所（表 = 2.3 / 変更の適用 = 2.4 / 引き渡しの配線 = 3.2 が使う。**それらが入った時点で外すこと**）。
- **2.2**: 保存は「文書のロックを保持したまま 1 パスで書き、成功時だけロック内で印を落とす」で確定（版は進めない）。**デッドロック検出のための時間切れがテスト内に 2 箇所**（`may_close` の非ブロッキング / 保存が進行中の適用を待つこと）あり、いずれも「速度の証拠ではない」旨をコメントに明記している。ロック待ちのテストは librs の実行を約 10 秒延ばす（許容）。
- **2.3**: 型名は crate 可視の `Sessions`（公開面の `DocumentSessions` は 2.5 が作る）。**同時要求の同一性テストはスピン門（`AtomicUsize` + `AtomicBool`）で揃える** — レビューの `Barrier` 案はこの環境で退行の検出が 8/10 だった（起床遅延で取り逃す）。スピン門は検出 10/10・誤検出 0/10（実測はテストのコメントに残した）。`forget` の「表のロック外で Drop」は正しいが**現行の型では観測できない**（コメントで固定）。**他方のウィンドウの未保存の観測は 2.4 の受入**（`unsaved` を立てる経路が 2.3 に無いため）。
- **2.4**: `change::edit` は **1 つの Guard の生存範囲で「判定 → 閉包 → 記録」を行う**（`Slot::lock_for_change` で Guard を取り、`Slot::record_edit(&guard, value)` が Guard を型で要求する）。ただし**「同じ Guard であること」は型では強制されない**（Guard を取り直す変異はコンパイルが通り、レビューの変異 B がそれを実証した）— 担保は**コードの形状**であり、その旨を doc に明記した。**`Slot::with_document_mut` は production 未使用**（記録しない貸出口であり、使うと要件 4.1 の抜け道になる）。タスク 2.5 が削除か `#[cfg(test)]` 化を決める。**このツールチェーンに `cargo fmt` は無く、整形は親の `qlty fmt` が担う**。
- **2.5**: 公開面は `lib.rs` の trait `DocumentSessionsApi`（11 メソッド）と具象 `DocumentSessions`（オブジェクト安全でない旨を doc に明記）。**セッションを作るのは `resolve` / `attach` / `create` の 3 つだけ**であることは、**根の名前の統合テストでは検出できない**（未解決の `Slot` と不在は根から区別できない）— そのため `lib.rs` の内部テストで私有の表を直接観測する（変異 M1/M2/M3 で落ちることを実測）。`with_document_mut`（記録しない可変貸出）は **`#[cfg(test)]` に閉じた**（production の可変経路は `change::edit` ただ 1 つ）。`#[allow(dead_code)]` の seam はすべて除去。
- **3.1（境界の数の門の変更・重要）**: 本タスクは `crates/app-shell/src/ipc/mod.rs` の生成物全体の検査を `assert_no_numeric_type`（`number` を禁じる）から **`bigint` だけを禁じる形**へ弱めた。理由は本スペックの境界が**シートの件数を `u32` で運ぶ**ためであり、`u32` は IEEE 754 の倍精度で正確に表せるので `number` へ落ちても値を取り違えない。**これは app-shell の不変条件（`ipc-contract.md` の「64 ビット整数を出さない」）を `bigint` についてのみ保つ形であり、`i64`/`u64`/`i128`/`u128` を禁じる趣旨は変えない** — number の全面禁止は `u32` の件数と両立しないため、数値を含まない型には従来どおり `assert_no_numeric_type` を個別に当てている（`ipc/mod.rs` のテスト doc と tests に実測がある）。**この弱め方は、以前にテスト自身の doc コメントが掲げていた「境界の型を数値で露出させない」という強い不変条件より緩い**ので、下流（`data-grid` 等）が境界へ `number` を出すときは**64 ビットを出さない規約を自分で守ること**（門は `bigint` しか止めない）。
- **3.1**: 境界の判別可能な合併型は**既存 3 つ（`IpcResult` / `WindowCloseVerdict` / `DocumentPickOutcome`）と同じ内部タグ + PascalCase** に揃えた（`DocumentSessionStatus` は `state` タグで `"Absent"` / `"Open"` / `"Unavailable"`。`DocumentOrigin` だけは既存に合わせて小文字の値を持つ）。**doc に生成物の実際の綴りを書くこと**（「小文字」と誤記するとフロントエンドが `case "absent"` と書いて絞り込みが静かに効かなくなる）。生成物の正例テスト（`bindings_declare_the_document_surface`）を足した — ドリフト検査だけでは「宣言を消して再生成」を取り逃す。
- **3.2**: `src-tauri` は **`document-format` を `[dev-dependencies]` のみ**に持つ（テストで本物の文書を作るため。**通常依存には足さない** — 配布物の依存グラフを増やさない）。宿主の連鎖は `install` の中で `port.host()` → `port.install(...)` の順に取り出す。**実装者は報告前に落ちたが、`cargo test -p jxcel` は 111 passed（`verification-triggers` 付きで 123 passed）で作業自体は完了していた**（親が証拠を補ってレビューへ回した）。
- **3.3**: セッションを作る 3 つの入口は**適応層の `WindowDestroyWatch`**（`session/watch.rs`）に閉じた。**コマンド（3.4）と宿主の連鎖（3.2）はどちらもこの入口を通る** — 宿主が表を直接触ると購読を伴わないセッションが生まれ、要件 1.5 が破れる（`host.rs` は `attach` を入口経由に切り替えた）。**管理状態へ置くのは `Arc<WindowDestroyWatch>` であり `Arc<DocumentSessions>` ではない**（登録済みラベルの集合が 2 つに割れると購読が二重になる）。破棄の購読は `WebviewWindow::on_window_event` を**テストから駆動できない**（`tauri::test` の `MockWindowDispatcher::on_window_event` は渡された閉包を保持しない。`mock_runtime.rs:711`）ため、`WindowDestroyEvents` の縫い目 1 つに閉じ、本番は `TauriWindowEvents` が担う（`window/geometry.rs` の `GeometryRead` と同じ形）。`resolve` / `create` / `forget_unresolvable` の `#[allow(dead_code)]` の縫い目は 3.4 が除去した。レビューの指摘（非阻害）: 登録済みラベルの検査と挿入は原子的でないため、同じラベルへの同時の初回入口が 2 つの購読を作りうる（IPC 駆動の入口では影響しないが design の「ウィンドウ 1 つにつき 1 回」より弱い）。
- **3.4**: 4 コマンドの本体は **Tauri に依らない自由関数（`answer_state` / `answer_new` / `answer_discard` / `answer_save`）**に切り出し、`#[tauri::command]` の関数は `AppHandle` と注入された `WebviewWindow` を取って呼ぶだけにした（テストは `AppHandle` を要さず本体を直接駆動できる）。**通知の要否は操作ごとに決め打ちせず、`should_notify(before, after)` という唯一の規則**（状態の等価性 + `Absent` への落下を除く）で決める — 決め打ちすると「既に未保存でない文書への破棄の印」のような**変えない操作**でもイベントが飛ぶ（実装者は実起動でこの誤通知を検出して単一規則へ直した）。**`Absent` 節（送り先が無い変化は送らない）は隣の掃除テストでは到達できない** — セッションを持たないラベルでは `before == after == Absent` となり `before != after` で短絡する。到達させるには**生きた窓で本物の文書を読んでから二重の `has_window` を倒し**、次の `resolve` の `register` に `register`→`release` を通させる（`a_window_that_disappears_after_loading_changes_to_absent_without_a_notification` が唯一の番人。節を落とすとこの 1 件だけが落ちることを実測）。**保存は `async fn` + `spawn_blocking`** で、`spawn_blocking` が異常終了したときだけ `IpcError::Document` に落ちる（それ以外の失敗はすべて成功腕）。`#[allow(dead_code)]` の縫い目は 3.3 の 3 件・3.5 の 7 件とも本タスクで除去し、`cargo clean -p jxcel` 後の全再構築で警告 0 件を確認した（早期除去はビルドが落ちる）。実画面での GTK 保存ダイアログの取り消し操作は**この環境では観測できなかった**（xdotool / wmctrl 無し、AT-SPI のバスに到達できない）— 取り消しで書き出しが起きないことは本物のコアと実ファイルシステムを使う単体テストで担保している。
