# Requirements Document

## Introduction
本機能は、型付きのシートを人が実際に読み書きするための画面を所有する。ドキュメント形式が値を保持し、型システムが値の正否を決めるところまでは既に成立しているが、それを人が見て触る手段が存在しない。10 万行を引っかかりなく走査でき、セルを直接打ち替えられ、型に応じた入力手段が現れ、違反がその場で分かる — この 4 つが揃って初めて本製品は道具になる。

本機能は同時に、後続機能が乗るための土台を 2 つ所有する。1 つは取り消しとやり直しの履歴であり、数式の再計算とマクロの実行が後から同じ履歴に加わる。もう 1 つはセルの入力手段の登録簿であり、ユーザー定義型が自分の入力手段を持ち込む先になる。どちらも利用者が現れてから形を決めると歪むため、本機能が先に定める。

本機能は表示と操作だけを所有する。値が型に適合するかの判断、スキーマそのものの変更、数式の評価、ファイルへの保存はいずれも所有しない。

## Boundary Context
- **In scope**: 大規模シートの表形式の表示と走査、セルの選択と移動、セルの編集と型に応じた入力手段、型強制の結果と検証違反の提示、違反箇所への移動、入れ子の列の展開表現と入れ子の値の詳細表示、行の追加・削除・複製、範囲のコピーと貼り付け、列幅・列の並び順・並べ替え・絞り込みの表示上の制御、編集操作の取り消しとやり直し、セルの入力手段の登録簿の定義、これらの応答時間と資源、実用水準のグリッドが 3 つの OS で描画されること

- **Out of scope**: 値が型に適合するかの判断と型強制の規則、スキーマの宣言と変更の画面、数式の入力と再計算、マクロの実行、ドキュメントのファイルへの読み書きと保存、変更履歴と差分の表示、シート間参照をたどる画面遷移、添付ファイルの実体の選択と管理、ユーザー定義型ごとの入力手段の実装

- **Adjacent expectations**:
  - 値の正否と型強制の規則は型システムを所有する機能が決める。本機能は判定を求めて結果を提示するだけであり、独自の判定規則を持たない
  - 編集経路では違反する値も保持できることが既に定められている。本機能は違反する値を書き戻せないものとして扱わず、違反として示したうえで保持する
  - 列の集合と並び順はスキーマから供給される。本機能が行う並べ替えは表示に閉じ、スキーマ上の列順を変更しない。列の追加・削除・型の変更はスキーマ編集を所有する機能が行う
  - 画面の配置・遷移・配色・例外の隔離はシェルを所有する機能が持つ。本機能は画面 1 つとして差し込まれる
  - 表示する対象のシートを選ぶ手段は本機能の外にある。本機能は与えられた 1 つのシートを表示する
  - 取り消しとやり直しの履歴は本機能が所有し、数式の再計算とマクロの実行が後から同じ履歴に加わる。加わる側が履歴の形を変えられない形で定める
  - セルの入力手段の登録簿は本機能が定義し、ユーザー定義型を所有する機能が登録する
  - 3 つの OS で描画が成立することを確認する最小の画面は既に存在する。本機能はそれを実用水準の画面として成立させる責任を負う
  - ドキュメントを開いて保持し、変更を書き戻し、保存する機能が別に存在する。本機能はそこから与えられたシートを表示し、編集をその機能を通して反映する
  - 編集の結果をファイルへ書き出すこと、その履歴を残すことは別の機能が所有する。本機能は編集をドキュメントへ反映するところまでを担う

## Requirements

### Requirement 1: 大規模シートの表示と走査
**Objective:** As a 10 万行の台帳を日常的に開くユーザー, I want 行数に関わらず表がすぐ現れ、引っかかりなく走査できること, so that データが育っても道具としての感触が変わらない

#### Acceptance Criteria
1. The Data Grid shall 1 つのシートにつき 10 万行かつ 30 列のデータを表示できるようにする。
2. The Data Grid shall 行の位置と列の名前を、走査している間つねに参照できる形で提示する。
3. The Data Grid shall 現在の表示位置がシート全体のどのあたりであるかを提示する。
4. When ユーザーが表の先頭または末尾へ直接移動したとき、the Data Grid shall 中間の行を順にたどることなく該当する位置を提示する。
5. If シートに行が 1 件も存在しないとき、then the Data Grid shall 列の構成を提示したうえで、行が存在しないことを示す。
6. If シートに列が 1 件も宣言されていないとき、then the Data Grid shall 表を描かず、スキーマが定義されていないことを示す。
7. When 表示中のシートの内容が本機能以外の経路で変更されたとき、the Data Grid shall その変更を表示へ反映する。

### Requirement 2: セルの選択と移動
**Objective:** As a キーボードで素早く動きたいユーザー, I want 現在位置と選択範囲がつねに明確で、キーボードだけで移動できること, so that 大量の入力作業が手を止めずに進む

#### Acceptance Criteria
1. The Data Grid shall 現在位置となるセルを 1 つ持ち、その位置を他のセルと区別できる形で提示する。
2. When ユーザーが方向の指示を行ったとき、the Data Grid shall 現在位置を隣接するセルへ移動する。
3. The Data Grid shall 連続した矩形の範囲、行の全体、列の全体のそれぞれを選択できるようにする。
4. When 現在位置が表示範囲の外へ移動したとき、the Data Grid shall その位置が見える状態になるまで表示範囲を追従させる。
5. The Data Grid shall 選択されている範囲に含まれる行数・列数・セル数を確認できるようにする。
6. When 選択範囲が確定したとき、the Data Grid shall その範囲を、複製・貼り付け・削除・取り消しの対象として扱う。

### Requirement 3: セルの編集と型に応じた入力
**Objective:** As a 表計算のように直接打ち込みたいユーザー, I want セルをその場で打ち替えられ、列の型に合った入力手段が現れること, so that 型を意識しなくても正しい値が貯まる

#### Acceptance Criteria
1. When ユーザーがセルの編集を開始したとき、the Data Grid shall その列の型に対応する入力手段を提示する。
2. The Data Grid shall 日時の型について暦による選択を、選択肢を持つ型について選択肢の一覧を、真偽の型について二値の切り替えを、それぞれ入力手段として提示する。
3. When ユーザーが編集を確定したとき、the Data Grid shall 入力された値を型システムの判定に掛けたうえで、その結果とともにドキュメントへ反映する。
4. If 入力された値が型強制によって変換されたとき、then the Data Grid shall 変換が行われたことと変換前の値を確認できる形で提示する。
5. If 入力された値が列の型に適合しないとき、then the Data Grid shall その値を破棄せずに保持したうえで、違反として提示する。
6. When ユーザーが編集を取り消したとき、the Data Grid shall 編集前の値を復元し、ドキュメントを変更しない。
7. The Data Grid shall 値なしを許す列について、値を消して値なしへ戻せるようにする。
8. The Data Grid shall シート間参照の型について、参照先のシートに存在する行から選ぶ入力手段を提示する。

### Requirement 4: 検証違反の提示と走査
**Objective:** As a 10 万行のうちどこが壊れているかを知りたいユーザー, I want 違反がその場で見え、離れた位置の違反にもたどり着けること, so that 型の保証が見つけられる形で役に立つ

#### Acceptance Criteria
1. While 表示されているセルに違反が存在するとき、the Data Grid shall そのセルを違反として区別できる形で提示する。
2. When ユーザーが違反しているセルを指定したとき、the Data Grid shall 違反の理由を提示する。
3. The Data Grid shall 表示中のシートに存在する違反の総数を提示する。
4. When ユーザーが次の違反への移動を指示したとき、the Data Grid shall 表示範囲の外にある違反であっても、その位置へ現在位置を移動する。
5. When 違反が入れ子の値の内側にあるとき、the Data Grid shall 入れ子のどの位置が違反しているかを特定できる形で提示する。
6. When 編集によって違反が解消されたとき、the Data Grid shall そのセルの違反の提示を取り下げる。

### Requirement 5: 入れ子の列の表現
**Objective:** As a 入れ子の構造を含む表を扱うユーザー, I want 入れ子が 2 次元の表の中で破綻せずに読めること, so that 表の形に収まらないデータも同じ画面で扱える

#### Acceptance Criteria
1. The Data Grid shall 入れ子の型を持つ列について、その内側のフィールドを列として展開できるようにする。
2. When ユーザーが展開された列を折りたたんだとき、the Data Grid shall 内側の列を隠し、元の 1 つの列として提示する。
3. The Data Grid shall 展開の状態を列ごとに保持し、走査によって失われないようにする。
4. The Data Grid shall 列として展開する入れ子の深さに上限を定め、上限を超える深さの値については詳細の表示へ誘導する。
5. When ユーザーが入れ子の値の詳細表示を開いたとき、the Data Grid shall その値の構造の全体を、各フィールドの型とともに提示する。
6. The Data Grid shall 同一の型の並びを持つ列について、その要素数を提示する。
7. If 入れ子の値の詳細表示の中で編集が行われたとき、then the Data Grid shall その編集を、型の判定・違反の保持・取り消しのいずれについてもセルの編集と同じ規律で扱う。

### Requirement 6: 行の追加・削除・複製
**Objective:** As a 台帳へ記録を足し続けるユーザー, I want 行を足し・消し・複製できること, so that 表がデータの入れ物として実際に使える

#### Acceptance Criteria
1. When ユーザーが行の追加を指示したとき、the Data Grid shall 指定された位置に行を追加し、値が与えられていない列には既定値を適用する。
2. When ユーザーが選択した行の削除を指示したとき、the Data Grid shall 選択されているすべての行を削除する。
3. When ユーザーが選択した行の複製を指示したとき、the Data Grid shall 選択された行と同じ値を持つ行を追加する。
4. If 複製によって一意制約を持つ列に重複が生じたとき、then the Data Grid shall 複製を中止せず、重複を違反として提示する。
5. If 削除の対象が 1 つの画面に収まらない行数であるとき、then the Data Grid shall 削除する行数を提示したうえで確認を求める。
6. The Data Grid shall 行の追加・削除・複製のそれぞれを取り消しとやり直しの対象とする。

### Requirement 7: コピーと貼り付け
**Objective:** As a 既存の表からデータを移したいユーザー, I want 範囲を選んで写せ、他のアプリケーションとも行き来できること, so that これまでの資産を捨てずに移行できる

#### Acceptance Criteria
1. When ユーザーが選択範囲の複製を指示したとき、the Data Grid shall 選択された範囲の値を、行と列の配置を保った形で複製する。
2. The Data Grid shall 複製した内容を、行の区切りと列の区切りを持つ一般的な表形式として他のアプリケーションへ渡せるようにする。
3. When 表形式のデータが貼り付けられたとき、the Data Grid shall 貼り付け先の各列の型に従って、それぞれの値を型システムの判定に掛ける。
4. When 貼り付けの範囲が既存の行数を超えるとき、the Data Grid shall 不足する行を追加したうえで貼り付けを完了する。
5. If 貼り付けられた値の一部が列の型に適合しないとき、then the Data Grid shall 適合する値の反映を中止せず、適合しない値を違反として保持したうえで、違反の件数を提示する。
6. The Data Grid shall 1 回の貼り付けを、取り消しとやり直しにおける 1 つの操作として扱う。
7. When 1 万行分の貼り付けが行われたとき、the Data Grid shall 行ごとの確認を求めることなく完了する。
8. The Data Grid shall 複製と貼り付けを、メニューからの選択とキーボードからの指示のいずれによっても実行できるようにする。

### Requirement 8: 列幅・列の並び順・並べ替え・絞り込み
**Objective:** As a 目的のデータだけを見たいユーザー, I want 見方を自由に変えられ、それがファイルを汚さないこと, so that 見方を変えても変更履歴が意味を保つ

**方針の根拠:** 本製品の中心価値は「いつ・誰が・どのセルを変えたか」が追えることである。並べ替えが保存される順序を書き換えると、並べ替え 1 回で全行が変更されたように見え、この価値が失われる。したがって本機能の並べ替えと絞り込みは表示に閉じる。

#### Acceptance Criteria
1. The Data Grid shall 列ごとに幅を変更できるようにする。
2. The Data Grid shall 表示上の列の並び順を変更できるようにする。
3. The Data Grid shall 1 つ以上の列を基準として行を並べ替えて表示できるようにする。
4. The Data Grid shall 列の値による絞り込みで、表示する行を限定できるようにする。
5. The Data Grid shall 列幅・列の並び順・並べ替え・絞り込みのいずれについても、ドキュメントに保存される行の順序および列の順序を変更しない。
6. While 並べ替えまたは絞り込みが適用されているとき、when セルが編集されたとき、the Data Grid shall 編集を画面上の位置ではなく対象の行そのものへ反映する。
7. While 絞り込みが適用されているとき、the Data Grid shall 絞り込みによって表示されていない行の数を提示する。
8. When 並べ替えの基準となっている列の値が編集されたとき、the Data Grid shall 編集した行の表示位置を編集の確定と同時に移動させない。
9. If 絞り込みが適用されている状態で複数の行にわたる貼り付けが行われたとき、then the Data Grid shall 表示されている行にのみ値を反映する。

### Requirement 9: 取り消しとやり直し
**Objective:** As a 大量の編集を行うユーザー, I want どの操作も取り消せ、やり直せること, so that 失敗を恐れずに手を動かせる

#### Acceptance Criteria
1. The Data Grid shall セルの編集、行の追加・削除・複製、貼り付けのそれぞれを取り消しの対象とする。
2. When ユーザーが取り消しを指示したとき、the Data Grid shall 直前の操作が行われる前の状態を復元する。
3. When ユーザーがやり直しを指示したとき、the Data Grid shall 取り消した操作を再び適用する。
4. When 取り消しの後に新しい操作が行われたとき、the Data Grid shall やり直しの対象を破棄する。
5. The Data Grid shall 取り消しの履歴を、シートごとではなくドキュメントごとに保持する。
6. The Data Grid shall 取り消しの履歴に保持する操作の数に上限を定め、上限を超えたときは古い操作から破棄する。
7. The Data Grid shall 取り消しの履歴を、数式の再計算およびマクロの実行による変更が同じ履歴に加われる形で提供する。
8. When 取り消しまたはやり直しが行われたとき、the Data Grid shall 対象となった範囲へ現在位置を移動し、変更された箇所が見える状態にする。
9. The Data Grid shall 取り消しとやり直しを、メニューからの選択とキーボードからの指示のいずれによっても実行できるようにする。

### Requirement 10: セルの入力手段の登録簿
**Objective:** As a 独自の型を持ち込むユーザー, I want 自分の型に合った入力手段がグリッドに現れること, so that 拡張した型が組込の型と同じ使い勝手で扱える

#### Acceptance Criteria
1. The Data Grid shall 型と入力手段の対応を登録できる登録簿を提供する。
2. The Data Grid shall 組込のそれぞれの型に対応する入力手段を、この登録簿を通じて提供する。
3. The Data Grid shall 入力手段の追加を、登録簿への登録のみで成立させる。
4. When 登録簿に登録されていない型のセルが編集されたとき、the Data Grid shall 値をそのまま扱える既定の入力手段を提示する。
5. The Data Grid shall 登録された入力手段に対しても、型の判定・違反の提示・取り消しの規律を組込の型と同一に適用する。
6. If 同一の型に対して入力手段が重複して登録されたとき、then the Data Grid shall 重複を検出し、登録を行った側へ報告する。

### Requirement 11: 応答時間と資源
**Objective:** As a 10 万行を日常的に扱うユーザー, I want どの操作でも待たされないこと, so that 規模が大きいことが道具の使い勝手を損なわない

**予算の根拠:** ドキュメント形式の要件は「10 万行を 3 秒以内に開く」を定め、型システムの要件は「10 万行 × 30 列の全件検証を 1 秒以内」を定めている。開く操作の内側で全件検証が走るため、表示側に許される予算はその残りである。ここで定める最初の画面の 1 秒はその残りに収まる上限である。

#### Acceptance Criteria
1. While 10 万行のシートが表示されているとき、when ユーザーが連続した走査を行ったとき、the Data Grid shall 毎秒 60 回の描画の更新を維持する。
2. When 10 万行のシートの表示が指示されたとき、the Data Grid shall 1 秒以内に最初の画面を提示する。
3. When セルの編集が確定されたとき、the Data Grid shall 100 ミリ秒以内に反映後の表示を提示する。
4. When 1 つのセルが編集されたとき、the Data Grid shall そのセルの判定のためにシート全件の検証を行わない。
5. When 1 万行分の貼り付けが指示されたとき、the Data Grid shall 3 秒以内に完了する。
6. When 表示の対象が 1 万行から 10 万行へ増えたとき、the Data Grid shall 表示のために確保する資源を行数に比例して増やさない。
7. The Data Grid shall 上記の所要時間を、SSD を搭載した 4 コア以上の一般的なデスクトップ環境における計測で満たす。

### Requirement 12: 3 つの OS における実用水準の描画の成立
**Objective:** As a Windows / macOS / Linux のいずれかで jxcel を使うユーザー, I want どの環境でもグリッドが実際に描画され操作できること, so that 環境によって中心機能が使えないという状態に陥らない

#### Acceptance Criteria
1. The Data Grid shall Windows / macOS / Linux のいずれにおいても、10 万行のシートを走査でき、セルを編集できるようにする。
2. If 実行環境の制約により表の描画が成立しないとき、then the Data Grid shall 無内容の領域を提示したまま留まらず、描画が成立しなかったことを識別できる情報を提示する。
3. If 描画が代替の経路へ切り替わったことにより走査の滑らかさが要件を満たさなくなったとき、then the Data Grid shall その事実を診断情報に記録する。
4. The Data Grid shall 3 つの OS のそれぞれについて、10 万行の走査と編集が成立したことを、実際に起動して観測した結果で確認できるようにする。
