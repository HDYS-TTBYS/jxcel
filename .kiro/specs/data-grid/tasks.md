# Implementation Plan

> **前提（このスペックの外）**: `document-session` が開いた `Document` をウィンドウ単位で保持していることを要するのは **6.2 / 6.3 / 7.3 / 群 8 の全体 / 9.2 / 9.3** である。それ以外（群 1〜5、6.1、7.1・7.2・7.4・7.5・7.6、9.1）は `document-format` と `schema-engine` だけで完結するため先行できる。`document-session` の design が確定した時点で、6.1 の境界用の型と 6.2・6.3 の適応層を再検証する（design.md の Revalidation Triggers）。

- [ ] 1. Foundation: クレートの足場・上流の拡張・成立性の実測
- [ ] 1.1 クレートをワークスペースへ追加し、tauri 非依存を検査に載せる
  - `crates/data-grid/` をライブラリクレートとして作り、ワークスペースの `members` に登録する
  - `document-format` と `schema-engine` への path 依存だけを持つ。`app-shell` へは依存しない
  - `Cargo.toml` の冒頭に依存方針のコメントを置く（`tauri` を推移的にも入れない、依存してよい兄弟は 2 つだけ、境界用の型をここに置かない理由）
  - `criterion` を dev-dependency に加え、`[lib] bench = false` と併記してベンチターゲットを宣言し、**同時に空のベンチファイルを置く**（宣言だけでは `cargo bench --no-run` が通らない）
  - **CI の段を足す必要はない。**コアクレートの tauri 非依存検査は引数なしで `crates/` 配下を全列挙する形になっており、新しいクレートは自動的に対象に入る。**対象に入っていることを実際に確かめる**
  - `cargo test` と `cargo bench --no-run` が成功し、`cargo tree -p data-grid` に `tauri` が現れない。`tauri` を依存に足すと検査の段が落ちる
  - _Requirements: 11.1, 11.7_

- [ ] 1.2 上流のドキュメントモデルに行の削除と位置指定の挿入を足す
  - `Document` に、複数の行識別子を受けて**取り除いた行を所有権ごと返す**削除を追加する（取り消しが値と識別子の双方を要するため。行は複製できない）
  - `Document` に、シート内の位置を指定して空の行を挿入する操作を追加する
  - 未知のシート・未知の行・範囲外の位置を、既存の誤り型の規律に沿って判別可能な変種として返す
  - **決定的な出力と往復の契約に触れない。**変わるのは行の集合と並びだけであることを、既存の決定性テストが通ることで示す
  - 削除した行を挿入で戻すと、識別子・値・位置が元に戻ることをテストで示す
  - _Requirements: 6.1, 6.2_

- [ ] 1.3 横断する座標の型と誤り型を定義する
  - セルの位置（行識別子と列の添字の対）、可視行の序数、行の区間、セルの範囲を型として定義する
  - **可視行の序数と物理的な行の位置を型の上で区別する**（絞り込みが効いている間に取り違えると、別の行を編集する）
  - 誤り型を判別可能な列挙体として定義し、診断に必要な文脈だけを持たせ、表示用の文言を持たせない
  - **値の不適合を誤り型に含めない。**違反は型システムが返すものであり、処理を止めない
  - 入れ子の内側の位置を、上流の違反報告が持つ経路の表現から写せることをテストで示す
  - _Requirements: 1.6, 2.3, 2.5, 4.5_

- [ ] 1.4 テストとベンチが共有する標本の生成器を用意する
  - 指定した行数・列数のシートと、それに適合するスキーマ宣言を組み立てる生成器をテスト用の共有モジュールとして置く
  - 組込の各型・入れ子・一意制約・必須を含む、現実に寄せた列構成を作れるようにする
  - 違反になる値を任意の割合で混ぜられるようにする
  - ベンチからは相対パス指定でこの共有モジュールを取り込む
  - 10 万行 × 30 列の標本が生成でき、同じ引数なら常に同じ内容になることをテストで示す
  - _Requirements: 1.1, 11.7_

- [ ] 1.5 グリッドライブラリを導入し、React 19 上で動くことを確かめる
  - `@glideapps/glide-data-grid` を `6.0.4-alpha24` に固定して追加する（**stable 6.0.3 は React 19 を受け付けない**）
  - 版を固定した理由と、上流が停滞していること、取り込みが退路であることを依存の追加箇所に注記する
  - 生成した標本を描く使い捨ての画面を、検証専用の経路に置く（出荷物に到達経路を作らない）
  - 型検査・lint・ビルドが通り、画面が 10 万行分の縦の広がりを持って描画される
  - _Requirements: 12.1_

- [ ] 1.6 10 万行の走査を実測し、描画層の採否を決める
  - 使い捨ての画面で 10 万行 × 30 列を走査し、フレーム時間の中央値を記録する
  - **Linux の結果を判断の拘束条件とする。**最も危険な環境であり、ここが通らなければ他の 2 つを測る意味がない。Windows と macOS の数値は 9.2 の観測で確かめる
  - 回避の環境変数（明示同期の無効化 → DMA-BUF レンダラの無効化 → 合成の無効化）の有無それぞれで測る
  - 塗った図形を読み戻して、描画が実際に成立したことを確かめる（DOM はあるが何も塗られない症状を捕まえるため）
  - 計測は**既存の 3 OS の検証マトリクスに一時的な段を足して**行い、新しい系統を作らない
  - **これは判断点である。**毎秒 60 回に届かない場合、7.2 の実装を自前 canvas に切り替える判断を記録する
  - 実測値と採否の判断が `research.md` に追記されている
  - _Requirements: 11.1, 12.1, 12.2_

- [ ] 2. Core: 行の順序と列の構成
- [ ] 2.1 並べ替えの順序を導出する
  - 1 つ以上の基準列から可視行の順序を導出する。比較は表示文字列ではなく値の変種ごとの順序で行う
  - 並べ替えは安定とし、同値の行は行識別子の順に並べる
  - **ドキュメントの行の並びを書き換える経路を持たない**ことを、可変参照を受け取らない形で型の上で示す
  - 同一のドキュメントと同一の指定から常に同一の順序が出ることをテストで示す
  - _Requirements: 8.3, 8.5, 8.8_

- [ ] 2.2 絞り込みの行集合を導出し、隠れた行数を数える
  - 一致・部分一致・値なし・値あり・違反あり、の絞り込みを列ごとに指定できるようにする
  - 複数の絞り込みは積として扱う
  - 可視行数と隠れた行数の双方を返す
  - 絞り込みと並べ替えを同時に指定したとき、順序が絞り込み後の集合に対して定まることをテストで示す
  - _Requirements: 8.4, 8.5, 8.7_

- [ ] 2.3 入れ子の展開状態から列の構成を導出する
  - 入れ子の型を持つ列について、内側のフィールドを列として展開した構成を導出する
  - 展開の深さに上限を設け、上限を超える深さは展開せず詳細表示へ委ねる
  - 展開状態を列ごとに保持し、順序の再計算で失われないようにする
  - 同一の型の並びを持つ列について、要素数を導出できるようにする
  - 深さの上限を超える入れ子を持つスキーマで、列の構成が発散しないことをテストで示す
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.6_

- [ ] 2.4 可視行の序数に対する違反の索引を作る
  - シート全体の検証結果から、可視行の序数を鍵とする違反の索引を作る
  - 違反の総数を保持し、指定した位置から前方・後方の最も近い違反の位置を返せるようにする
  - 入れ子の内側の違反について、内側の位置を保った形で索引に載せる
  - **順序や絞り込みが変わったとき、索引の鍵を張り直す**
  - 表示範囲の外にある違反が探索で見つかることをテストで示す
  - _Requirements: 4.1, 4.3, 4.4, 4.5_

- [ ] 3. Core: 編集の適用
- [ ] 3.1 セルの編集を適用し、判定を型システムへ委ねる
  - 打たれた文字を受け取り、型システムの書き込み判定を**編集経路として**呼ぶ
  - 判定が返した値・変換・違反をそのまま写す。**独自の判定分岐を書かない**
  - 変換が起きた場合、変換前と変換後の双方を結果に含める
  - 1 セルの編集では、当該列に限定した再検証だけを呼び、シート全件の検証を呼ばない。**呼び出し回数を数える観測でこれを固定する**
  - 型に適合しない値が破棄されずドキュメントに残り、違反として報告されることをテストで示す
  - _Requirements: 3.3, 3.4, 3.5, 3.7, 11.4_

- [ ] 3.2 行の追加・削除・複製を適用する
  - 指定された位置への追加で、値が与えられていない列にスキーマの既定値を適用する
  - 選択された複数の行の削除を 1 回の操作として適用する
  - 複製で同じ値を持つ行を追加する。一意制約に重複が生じても**中止せず違反として報告する**（編集経路は拒否しないため）
  - 追加・削除・複製のいずれも、行数の変化を結果に含める
  - 一意制約を持つ列を含む行を複製すると、行が増えたうえで重複が違反として報告されることをテストで示す
  - _Requirements: 6.1, 6.2, 6.3, 6.4_

- [ ] 3.3 入れ子の値の編集を適用する
  - 入れ子のセルを、構造を保った表現として受け取り書き戻す
  - 上流のセル値と構造表現の相互変換を使い、独自の解析器を書かない
  - 入れ子の内側の違反が、内側の位置とともに報告されることを確かめる
  - 構造表現として解釈できない入力を、処理を止める誤りとして返す
  - 入れ子の値を編集して往復させると、編集していないフィールドが変化しないことをテストで示す
  - _Requirements: 5.5, 5.7_

- [ ] 3.4 表形式テキストを解釈し、範囲への貼り付けを適用する
  - 行の区切りと列の区切りを持つテキストを、セルの矩形として解釈する
  - 値の中に区切りが含まれる場合の囲みを解釈する
  - 貼り付けの範囲が既存の行数を超えるとき、不足する行を追加して完了する
  - 適合しない値があっても反映を中止せず、違反として保持したうえで件数を返す
  - **絞り込みが効いている間は、表示されている行にのみ値を反映する**
  - 1 万行分の貼り付けが、行ごとの判定ではなく一括の判定で完了することをテストで示す
  - _Requirements: 7.3, 7.4, 7.5, 7.7, 8.9_

- [ ] 4. Core: 取り消し履歴
- [ ] 4.1 命令と逆命令の対を積む履歴を実装する
  - 各編集命令に対する逆命令を**適用時に**生成する（適用後には作れないため）
  - 行の削除の逆命令が、取り除いた行の値・識別子・位置を保持する
  - 履歴をシートごとではなくドキュメントごとに保持する
  - 登録口を 1 つに絞り、**数式の再計算とマクロの実行のための区分を先に用意する**（後続スペックが履歴の内部構造に触れずに乗れるようにするため）
  - セルの編集・行の追加・削除・複製・貼り付けのそれぞれについて、逆命令の適用が元の状態を復元することをテストで示す
  - _Requirements: 6.6, 7.6, 9.1, 9.5_

- [ ] 4.2 取り消しとやり直しを適用し、上限と破棄を実装する
  - 取り消しで直前の操作の前の状態へ戻し、やり直しで再び適用する
  - 取り消しの後に新しい操作が行われたとき、やり直しの対象を破棄する
  - 保持する操作数の上限を設け、超えたら古い側から捨てる
  - 取り消しとやり直しの結果に、影響を受けた行を含める
  - 上限を超える回数の編集を行った後、最も古い操作が取り消せなくなることをテストで示す
  - _Requirements: 9.2, 9.3, 9.4, 9.6, 9.7_

- [ ] 5. Core: 窓の符号化と操作口
- [ ] 5.1 (P) 可視範囲の窓を二進形式へ符号化する
  - 頭に版・世代・開始序数・行数・列数を持ち、前方から 1 回の走査で復号できる形を定義する
  - 行識別子は生のまま運び、セルは表示文字列・変種の札・違反の有無で表す
  - **64 ビット整数と 10 進数を数値として出さない。**表示文字列として運ぶ
  - 入れ子のセルは要約（要素数など）を運び、構造そのものは運ばない。**内側のどの位置が違反しているかは札として運ぶ**
  - 符号化と復号の往復で、整数と 10 進数が文字列のまま保たれることをテストで示す
  - _Requirements: 1.1, 1.2, 4.5, 11.2, 11.6_
  - _Boundary: WindowCodec_
  - _Depends: 2.1, 2.2, 2.4_

- [ ] 5.2 画面 1 枚ぶんの操作口を組み立てる
  - 表示状態・行の順序・違反の索引・取り消し履歴を保持し、開く・列を返す・表示の指定を変える・窓を符号化する・編集を適用する・履歴を進める・次の違反を探す、を 1 つの操作口として公開する
  - **`Document` を所有せず**、呼び出しごとに参照または可変参照を受け取る
  - 編集・取り消し・やり直しの直後に、**判定が返した違反との差分で索引と総数を更新する**（全件検証を再実行しない）
  - 公開面を根の再輸出に集め、層の鎖の文言を各層の冒頭に置く
  - 編集で違反が解消されたとき総数が減り、新たな違反が生じたとき増えることを、全件検証を呼ばずに達成できることをテストで示す
  - _Requirements: 4.3, 4.6, 11.4_

- [ ] 6. Integration: 境界とコマンド
- [ ] 6.1 境界用の型を定義し、生成物を更新する
  - 列の情報・表示の指定・編集命令・判定の要約・違反の位置を、境界用の型として定義する
  - 型は**他のドメインクレートを参照せず**、文字列と 32 ビット以下の整数だけで構成する
  - **型の種別を表す札をここで定義し、生成物から出す。**フロントエンドの描画側と入力手段の登録簿は双方ともこの生成された札を取り込み、独自に定義しない
  - 生成の宣言に型を追加し、生成物を再生成する。**生成物を手で編集しない**
  - 生成物のドリフト検査とフロントエンドの型検査の双方が通る
  - _Requirements: 1.1, 1.5, 1.6, 3.2_

- [ ] 6.2 封筒つきのコマンドを登録し、権限を与える
  - シートを開く・表示の指定を変える・編集を適用する・履歴を進める・次の違反を探す、の 5 つを登録する
  - コマンド名を定数として単一の源に置き、文字列リテラルで書かない
  - 各コマンドに権限ブロックを定義し、与える集合へ所属させる。**片方だけでは配布物から静かに消える**
  - 呼び出し元ウィンドウは注入された値から取り、ペイロードで受け取らない
  - 登録名と許可の一致を検査する段が通り、5 つのコマンドが呼び出せる
  - _Requirements: 3.3, 4.4, 8.3, 8.4, 9.2, 9.3_

- [ ] 6.3 窓のコマンドを生バイト経路として登録する
  - 要求の頭を含む引数 1 つを受け取り、二進の窓を返すコマンドを登録する
  - **他の 5 つと同じ 3 点セットを揃える**: 名前の定数を単一の源に足し、登録の根へ 1 行足し、**専用の権限ブロックを定義して与える集合へ所属させる**
  - **引数を入れ子にしない**（入れ子にすると要素ごとの配列へ変換され、経路の意味が失われる）
  - 失敗と世代違いを空の窓で表す（この経路は封筒を運べないため）
  - フロントエンドの生バイト呼び出しの型に、このコマンドを加える
  - 登録名と許可の一致を検査する段が 6 つすべてについて通り、10 万行のシートから任意の位置の窓が取得でき、世代が古い要求が空で返る
  - _Requirements: 1.1, 11.2_

- [ ] 7. Core: フロントエンドの部品
- [ ] 7.1 (P) 描画層の移植口を定義し、偽の実装で契約を固定する
  - 描画・当たり判定・文字計測・クリップボードの配管だけを扱う移植口を定義する。編集の意味論・判定・履歴を知らせない
  - セルの取得は**同期であり例外を投げない**契約とし、未取得の行は読み込み中として返す
  - 選択の変化・編集の起動・列幅の変更・列の移動・複製・貼り付けを、移植口の呼び出しとして外へ出す
  - セルの種別の札は 6.1 の生成物から取り込む
  - テスト用の駆動器から移植口を動かし、偽の実装に差し替えても呼び出しの並びが変わらないことを示す（画面そのものは 8.1 で作る）
  - _Requirements: 2.1, 2.2, 2.3_
  - _Boundary: RendererPort_
  - _Depends: 6.1_

- [ ] 7.2 移植口の背後に描画層を実装する
  - 1.6 の判断に従って実装を選ぶ（グリッドライブラリまたは自前 canvas）
  - 走査・選択・列幅の変更・列の移動・複製・貼り付けの入口を移植口へ結線する
  - 10 万行のシートを走査でき、選択した範囲が視覚的に区別でき、列幅と列の位置が操作できる
  - _Requirements: 1.2, 1.3, 2.4, 7.1, 7.2_
  - _Boundary: GlideAdapter_
  - _Depends: 1.6, 7.1_

- [ ] 7.3 窓の記憶と先読みを実装する
  - 序数の区間を鍵とする窓の表を持ち、同期のセル取得を満たす
  - 走査の向きを見て前後の窓を先読みする
  - 同じ区間への要求を 1 本にまとめ、世代が変わった応答を捨てる
  - 影響を受けた行の通知を受けて該当する窓を捨てる
  - 未取得のセルが**空白ではなく読み込み中として**描かれる（空白は値なしと区別がつかないため）
  - _Requirements: 1.4, 1.7, 11.1, 11.2, 11.6_
  - _Boundary: WindowCache_
  - _Depends: 6.3, 7.1_

- [ ] 7.4 (P) セル入力手段の登録簿と組込の入力手段を実装する
  - 型と入力手段の対応を登録できる登録簿を定義する。**グリッド側に型ごとの分岐を書かない**
  - 鍵となる型の札は 6.1 の生成物から取り込み、独自に定義しない
  - 日時に暦による選択を、選択肢を持つ型に一覧を、真偽に二値の切り替えを、シート間参照に参照先の行からの選択を、それぞれ実装する
  - 未登録の型は値をそのまま扱える既定の入力手段へ落とす
