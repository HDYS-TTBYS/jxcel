# IPC 境界の契約

> `app-shell` が確立した、フロントエンドとドメインをつなぐ唯一の経路の規約。**残る全 UI スペックがコマンドを追加する**ため、ここに置く。詳細と実測は `.kiro/specs/app-shell/`（design.md「CommandSurface」・tasks.md の 2.x / 7.x の Implementation Notes）。

## 原則

境界は **1 本の型付き経路**である。各機能が独自の呼び出し口を作ると、型の不一致が実行時にしか見つからなくなる。**機能はコマンドを足すだけで、経路そのものには触れない。**

## コマンド名は単一の源に置く

- 正本は `crates/app-shell/src/ipc/command_names.rs` の配列（`COMMAND_NAMES`）。**名前を文字列リテラルで書かない**
- 登録は `src-tauri/src/commands/mod.rs` のマクロが単一の源。**各機能は自分のモジュールに関数を置き、根は列挙だけを行う**（根にロジックを書かない）
- 機械的に固定されていること: 登録名 ⊆ `COMMAND_NAMES`、登録名 == ハンドラの関数名、重複なし
- **改名・削除はスペック横断の変更**（ハンドラ登録・生成物・フロントエンドの 3 つが同時に壊れる）。design.md の Revalidation Trigger として扱う

```rust
// 名前は定数として足す（根もフロントもこれを参照する）
pub const DOCUMENT_OPEN: &str = "document_open";
```

## 呼び出し元ウィンドウは注入された値から取る

ハンドラは引数に `WebviewWindow` を取り、そこからラベルを得る。**ペイロードで受け取ってはならない**（偽装でき、ウィンドウとドキュメントの対応が崩れる）。境界の型 `WindowContext { window: WindowLabel }` を**再定義せず使う**。

```rust
#[tauri::command]
async fn document_open(window: WebviewWindow, request: Request) -> IpcResult<…> { /* window.label() */ }
```

## 応答は封筒で返す

- 成功・失敗は**判別可能な合併型**で返す。呼び出し側が網羅的に分岐でき、成功と失敗を取り違えない
- フロントエンドの薄いラッパは**解決値をそのまま返す**。**新しい封筒で包み直してはならない**（包むとドメインの失敗が成功として報告される。実装初期に実際に壊れた箇所）
- 封筒を作るのは**経路レベルの失敗だけ**（未知のコマンド・IPC 不在）。ドメインの失敗は封筒の失敗腕で返す
- **例外は生バイト経路だけである**（現在 **2 本**: `bulk_echo` と `grid_rows_window`）。大きなペイロードを JSON に通すと劣化するため、引数を全体のバッファとして受け取り、応答を生バイトで返す専用のコマンドを置く。この経路は封筒を使わないが、**「経路レベルの失敗だけが拒否になる」**という規律は同じ
- **本数を数えている記述をここに残さない。** 生バイト経路が増えたらこの行を更新する（`scripts/check-command-acl.sh` が見ているのは ACL の一致だけであり、経路の種類は数えていない）。`grid_rows_window` は `data-grid` の 6.3（窓の取得）が足した 2 本目であり、**引数のバイト配置（版・世代・開始序数・行数・シート長 + シートの UTF-8）は `src-tauri/src/commands/grid.rs` の「生バイト経路」の節が唯一の源**である（TS 側の符号化と両側を同時に直すこと）

## 型は 1 か所で定義し、生成物は手で編集しない

- ts-rs の derive を付けてよいのは `crates/app-shell/src/ipc/` の下だけ。**境界に 64 ビット整数を出さない**（TS の数値精度で壊れる）。**門が止めるのは `bigint`（= `i64`/`u64`/`i128`/`u128`）だけである** — `u32` の件数（`document-session` のシートの列数・行数）は `number` へ落ちても正確なので `number` の全面禁止は課していない（`document-session` の 3.1 が門をこの形へ弱めた。`crates/app-shell/src/ipc/mod.rs` の `bindings_contain_no_any_and_no_64_bit_numbers`）。**したがって `number` を境界へ出す型は自分で「64 ビットでないこと」を守ること**（門はそれを見ていない）
- `src/ipc/bindings.ts` は**追跡する生成物**。再生成は `cargo run -p app-shell --bin generate-bindings`。**手で直さない**（直すのは生成元）
- ドリフト検査は 2 段で成立する。**片方だけでは足りない**:
  - 生成物と `render_bindings()` のバイト比較 → 「Rust 側が変わったのに生成物が古い」
  - フロントエンドの型検査 → 「生成物は新しいのにフロントが追随していない」
- イベント名（設定変更など）も生成物に定数として出る。**綴りを手で書かず生成物を参照する**

## 権限を与えないとコマンドは消える

自前コマンドの ACL が有効になっているため、**登録しただけのコマンドは ACL の対象**になり、**どの capability も許可していないコマンドはビルド時に削除される**（拒否ではなく削除。配布物から静かに消える）。

- **コマンドを足したら権限も足す**（`src-tauri/permissions/app.toml` の定義と、与える集合への所属）。片方だけでは動かない
- 権限の付与は機械検査で一致を固定する（`scripts/check-command-acl.sh`）
- **フロントエンドにファイルシステムとプロセス起動の経路を与えない**（第一の制御はプラグインを依存に入れないこと。`scripts/check-forbidden-plugins.sh`）。権限を絞るのは第二の制御であり、両方要る

## メニュー項目の登録口

- 項目は**各機能が所有**し、登録口（`src-tauri/src/menu.rs`）に登録する。選択は登録時に渡したハンドラへ、**実イベントと同じ 1 つの経路**で届く
- ショートカットは**プラットフォームで解決した綴り**を渡す（`CmdOrCtrl` のような曖昧な指定は拒否される）。競合は**登録時に登録元へ報告**され、**黙って片方を捨てない**
- アプリ全体のメニューしか持てないプラットフォームでは、項目の位置と有効・無効をフォーカス移動のたびに再計算する（ウィンドウ単位の状態を持てないため）

---
_Override や例外を作らないこと。例外が必要なら、それは境界の設計を変える話である_
