# Product Overview

jxcel は、JSON をファイル実体とする「データベースとして運用できるスプレッドシート」である。単一実行ファイルとして Windows / macOS / Linux で動作し、ファイルの実体は ZIP 圧縮された JSON テキストであるため、git による意味のあるバージョン管理が既定で機能する。

対象は個人・パワーユーザー。「Excel では型が守れない、DB を立てるほどではない、しかし変更履歴は追いたい」という領域を埋める。

## Core Capabilities

- **型付きの表データ**: ファイル → シート → データスキーマ → 行 の階層。ネスト可能なスキーマ、DB 的なデータ型、`ANY`、そして JS による型定義の拡張
- **既定で有効なバージョン管理**: git を内蔵し、ユーザーが git を意識せずに履歴・差分・復元が使える。差分は「どの行のどの列がどう変わったか」として構造的に表示される
- **マクロに統合された計算**: 閉じた式言語を持たず、すべての計算を JS/TS マクロとして表現する。LSP 付きエディタと高機能な標準マクロライブラリがこれを支える
- **テンプレートへの連続書き出し**: 既存の xlsx / docx テンプレートにデータを差し込み、行数分のファイルを一括生成する
- **入力フォームの LAN 配信**: コンポーネントを配置してフォームを作り、アプリ内蔵サーバで同一ネットワークに配信する。スキーマを知らない人からも型の正しいデータを集められる

## Target Use Cases

- 個人が長期にわたって蓄積する台帳・在庫・記録の管理（変更履歴が価値を持つデータ）
- Excel の関数の限界に突き当たり、しかし別言語へ移行するほどでもない集計・変換作業
- 請求書・報告書など、テンプレートに差し込んで大量に書き出す定型業務
- 少人数からのデータ収集（フォームを配って集め、型が保証された状態で蓄積する）

## Value Proposition

xlsx はバイナリであるがゆえに「いつ・誰が・どのセルを変えたか」を失う。素の JSON には構造・型・シートの規約がない。専用の DB はセットアップと運用のコストが個人には見合わない。jxcel はこの三者の隙間を、**単一ファイル・単一実行ファイル・既定でバージョン管理**という形で埋める。

「関数はマクロに統合する」という設計判断がもう一つの軸である。Excel 関数の限界に達した時点で別の言語へ逃げる必要がなく、最初から最後まで同じ言語（TypeScript）で書き続けられる。

## Explicitly Not

以下は意図的な非目標であり、要望が来ても既定では拒否する。スコープを守ることが本プロジェクトの成立条件である。

- **大規模データ**: 1 ファイル約 10 万行・全件オンメモリが前提。遅延ロード・ページング・インデックスは持たない
- **複数人の同時編集**: 単一ユーザー・単一プロセスが前提。リアルタイム共同編集は範囲外
- **敵対的コードに対する防御**: マクロのサンドボックスは「事故防止」の水準であり、信頼できないマクロを安全に実行する保証はしない
- **インターネット公開**: フォーム配信は LAN 限定。クラウドホスティング・認証基盤・ユーザー管理は持たない
- **エンタープライズ機能**: 権限管理、監査ログ、暗号化、SSO は範囲外
